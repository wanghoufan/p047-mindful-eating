# 120.项目实战：优化 App 的 UI 样式

## 本课总结

1. 对比最开始生成的原型图和现在的截图，页面样式没有高级感，光球和引导语位置有偏差，改动范围太大会顾此失彼，所以按页面一个一个对齐。
2. Claude Code排查时发现缺少用户输入感受的页面，按我们选的方案只还原输入页的UI，语音按钮保留入口但暂不接真实的语音识别功能。
3. UI修复计划分成Home、Breathe和Focus三部分：补上输入页、对齐宽度间距和提示区域布局细节，确认计划后自动执行修改再发到安卓真机验证。
4. 真机检查遗留两个问题：首页卡片白底和呼吸光球不够立体，Claude Code改用SVG绘制光球并去掉白色填充，但光泽感还是弱了一些。
5. 换成把原型图和真机截图都放进项目让Claude自己对比，找出六个主要差异，再把所有用到光球的页面统一成和原型一致的样式。
6. 浅色和深色模式下完整测试首页、呼吸和专注，光球立体感明显了，动画、白噪音混音和计时功能都正常，这一轮UI优化基本搞定。
7. 把UI必须忠实还原原型图写进项目宪法，版本从1.0.0升到1.1.0成为长期规则，最后把这一轮改动推送到GitHub保存版本。

---

### 对照原型逐页对齐

先回头看一下最开始生成的原型图：原型里有深色模式、呼吸光球和比较完整的视觉层次，整体质感很强。再看现在的截图，差距还是比较明显的：页面样式没有高级感，呼吸页的光球和引导语位置也有偏差，还有不少细节需要修复。这次我们不打算让 Claude Code 一次性重做整个 App，改动范围太大很容易顾此失彼，所以我们按照页面一个一个对齐。这里把修改思路告诉 Claude Code，发送以后，它会先对比现有页面和原型，再判断哪些地方需要调整，我们先等它完成排查。

### 先补上缺失的输入页

再检查 Breathe 页面的时候，Claude Code 先发现了一个更基础的问题：现在缺少用户输入感受的页面。按照我们的产品设计，用户应该先输入自己当前的感受，再用 App 帮用户匹配合适的呼吸方式和引导语，但这个页面我们还没有做出来。所以 Claude Code 先问我们这次要做到什么程度：第一个方案是只把输入页的 UI 还原出来，AI 匹配和语音识别暂时不实现；第二个是连着后面的功能一起做；第三个是暂时跳过这一页。我们这里选择第一个，因为这次目标是先把 UI 对齐，AI 功能后面还有单独的开发阶段，不需要现在提前做。接着 Claude Code 又确认了语音输入要不要一起实现，这里同样先保留语音按钮和对应的 UI，但暂时不接真实的语音识别功能，这样页面结构可以先完成，功能后面再补。

### 三段式修复计划

方案确认以后，Claude Code 又生成了一份临时的 UI 修复计划，计划主要分成三个部分：Home、Breathe 和 Focus。Home 主要调整布局和视觉细节；Breathe 会补上输入页面，并且保留暂时不可用的语音入口；Focus 会继续对齐宽度、间距、内容长度和提示区域的布局细节。大致检查下来没问题，我们直接选择 Yes and Auto Accept，同意这个计划并且让 Claude Code 自动执行后续修改。接下来它就会按照这份计划修改主页 UI，我们等待它完成这一轮的调整。

### 真机复查留下两个问题

修改完成以后，我们重新部署到安卓真机上测试一下。发送以后，Claude Code 会重新完成安卓构建和安装，我们等它处理完成。App 运行起来以后可以看到，这次整体布局更接近原型图了，不过下面两个导航卡片出现了白色背景，这个问题先记下来待会再修复。接着点进 Breathe，现在已经补上了用户输入感受的页面：我们可以选择当前状态的标签，再点击 Find My Breath，之后先出现一个表示加载中的光球动画，匹配完成以后进入正式的呼吸引导页面，这里的光球也会跟着呼吸节奏放大和缩小。再回到首页进入 Focus 模式，整体布局和配色也已经比较接近原型图了。但整体看起来，目前还有两个比较明显的问题：一个是首页卡片的白底，另一个是最标志性的呼吸光球样式还不够接近原型。所以我们继续把问题明确告诉 Claude Code，发送以后让它对照原型修改，我们等它处理完成。

### 让 Claude 自己对比两张图

修复完之后，Claude Code 告诉我们，它把光球改成了用 SVG 来绘制，也去掉了首页卡片多余的白色填充。但我们再回到真机看看效果：首页卡片已经干净多了，光球也终于像一个完整的球体，但立体感和光泽感还是弱了一些。接着再进入 Breathe 页面看一下，这里又发现了一个问题：呼吸流程里其实有多个页面都会用到光球，但这次 Claude 只修改了部分位置，正式呼吸引导页面的光球还是原来的样式，说明这次修改还没有完全覆盖到所有使用光球的页面，接下来还是要继续统一。这次我们换一种方式：与其自己一点点描述哪里不像，不如直接把原型图截图和真机截图都放进项目里，让 Claude 自己对比。在对话里我们可以用 Add 直接引用这两个图片文件，让它根据图片找出差异。发送以后，Claude 会直接分析两张图的差异，它总结出了六个主要问题，包括首页布局、光球的界面方向、卡片样式这些。

### 统一所有页面的光球

既然差异已经找出来了，我们就直接让它继续修复。发送以后，Claude 接着刚才识别出的差异继续调整首页。我们等它修改完成，首页先改到这里，但我们还不着急马上重新打包测试，因为还有第二个问题需要一起处理。前面我们已经把首页的光球改成了新的样式，但 Breathe 里的光球还没有同步，所以这里继续让 Claude 全部改成和原型一致的样式。发送以后，Claude 会继续查找项目里所有用了呼吸光球的页面，再统一它们的样式，而不是不同页面各用一套。

### 完整测试与写入宪法

现在我们来完整测试一下这一轮的 UI 效果。先看首页：现在光球的光泽和立体感都更明显了，看起来更像一个真正的球体。接着进入 Breathe：主要确认这里的光球有没有和首页的统一，现在呼吸页面也已经换成同一套动态光球，并且会随着呼吸节奏自然放大和缩小，效果基本没问题。再看一下 Focus：白噪音混音台可以正常使用，计时功能也没有问题。接下来我们再测试一下之前一直没看的深色模式：打开手机设置把系统切换到深色模式，再回到 App，可以看到深色模式下整体质感会更强一些，首页的光球颜色还更透亮；进入 Breathe，呼吸光球和深色模式下首页的样式也是统一的，并且动画正常；最后再回到 Focus，白噪音播放功能和样式也都没问题。那到这里这一轮 UI 优化就基本搞定了。这里还有一个小技巧：为了后面继续开发新功能时 UI 不会越改越偏，我们可以把必须参考原型图直接写进项目宪法，把它变成后续开发都要遵守的长期规则。这里再次使用 Spec Kit 修改宪法，发送以后 Claude Code 会更新 Constitution.md。我们等待它修改的同时，也可以打开宪法看看具体增加了什么。这次修改以后，宪法版本从 1.0.0 更新到了 1.1.0，也就是说每次规则发生变化都会留下版本记录。新增的第六条原则就是 UI 必须忠实还原原型图，它还进一步明确了参考原型具体包括页面布局、信息层级、颜色、字体、间距、圆角、阴影、图标，以及组件状态和交互流程。这样每次通过 Spec Kit 推进开发时，Claude Code 读到宪法就会同时读到这条规则，知道在修改 UI 之前要先参考原型图，而不是自己重新设计。

### 推送版本收尾

接下来，这一轮我们完成了 UI 优化，也更新了项目宪法，所以先把当前改动推送到 GitHub 上面，顺便保存一个版本。发送以后，Claude Code 会整理当前改动并且完成提交和推送。我们等它操作完成，这样这一阶段的开发就告一段落了。我们下期见。
