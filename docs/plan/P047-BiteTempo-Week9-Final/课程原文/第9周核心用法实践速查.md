# 第 9 周核心用法实践速查

## 流程：用 Spec Kit 跑 SDD

- 新功能要让 AI 按规范推进而不自由发挥：用 Spec Kit 跑 SDD（规格驱动开发），先定规则、写规格、澄清、出计划、拆任务，再按任务实现。https://github.com/github/spec-kit ｜ 文档 https://github.github.io/spec-kit/
- Spec Kit 的命令以 Skill 形式装进所用智能体的目录（Claude Code 在项目的 `.claude/skills/`），换 Copilot、Codex、Cursor 等其他智能体走同一套集成。https://github.github.io/spec-kit/reference/integrations.html ｜ Claude Code 的 Skill 机制 https://docs.anthropic.com/en/docs/claude-code/skills
- Spec Kit 用 uv 安装 Specify CLI，再到项目目录执行 `specify init` 初始化。https://docs.astral.sh/uv/
- `/speckit.constitution` 生成项目宪法，把要长期遵守的原则一次写死：合规红线、指定框架、必须多语言、UI 以原型为准、AI 层不绑厂商。产物在 `.specify/memory/constitution.md`
- 之后要新增长期规则，继续写进项目宪法，而不是每次在对话里口头叮嘱；智能体每轮开发都会读到宪法。
- `/speckit.specify` 写需求规格：只写解决什么问题、有哪些功能、怎么算验收，技术选型留到计划阶段；一个需求一个编号目录 `specs/001-xxx/`。
- `/speckit.clarify` 在出计划前逐条澄清会影响产品行为的歧义（输入方式、数据是否留存、第一版功能边界）。
- `/speckit.plan` 生成技术计划，同时落 research / data-model / quickstart 等配套文档。
- `/speckit.tasks` 把计划拆成任务清单 tasks.md：按 Phase 分组，任务带 T001 这类编号，便于追进度。
- `/speckit.implement` 按 Phase 逐项实现；比直接说"把这个功能做出来"更贴文档、更少超出任务范围。

## 选型：什么需求配什么库

- 项目要同时出 iOS 和 Android App：用 Expo，一套 React Native 代码通吃两端。https://expo.dev/ ｜ https://docs.expo.dev/
- App 要管理页面与跳转（进详情页、切 Tab）：用 expo-router，按文件生成路由。https://docs.expo.dev/router/introduction/
- React Native 项目要写 UI 样式：用 NativeWind，把样式直接写在组件上，页面结构和样式在同一处，AI 改 UI 更准。https://www.nativewind.dev/
- 需要跟用户操作或页面状态实时联动的动画（缩放、拖拽、按钮反馈、页面转场）：用 Reanimated。文档 https://docs.swmansion.com/react-native-reanimated/ ｜ **效果演示** https://docs.swmansion.com/react-native-reanimated/examples/
- 要播放已经做好的成品动画文件：用 Lottie React Native，它不做实时控制；实时联动那类动画归 Reanimated。https://github.com/lottie-react-native/lottie-react-native ｜ 在线预览动效 https://lottiefiles.com/ ｜ https://airbnb.io/lottie/
- 要同时播放多路音频并逐轨控制音量、循环（例如白噪音混音台）：用 Expo Audio。https://docs.expo.dev/versions/latest/sdk/audio/
- App 要支持多语言：用 expo-localization 读手机系统语言 + i18next 管各语言文案，从第一版就配好。https://docs.expo.dev/versions/latest/sdk/localization/ ｜ https://docs.expo.dev/guides/localization/ ｜ https://www.i18next.com/
- App 要给他人分发或准备上架：用 EAS Build 云端打包 iOS/Android 安装包，它还能处理部分签名配置。https://docs.expo.dev/build/introduction/ ｜ 环境变量与密钥 https://docs.expo.dev/eas/environment-variables/
- App 要云端数据库、账号体系或文件存储：用 Supabase，托管 Postgres 且自带 Auth / Storage / Realtime。https://supabase.com/docs

## 真机实测

- Expo 项目本地跑起来的命令入口：`npx expo start` 起开发服务器；`npx expo run:android`、`npx expo run:ios --device` 构建带原生能力的版本。https://docs.expo.dev/more/expo-cli/
- 用到手机原生能力（通知、权限、拍照、蓝牙、陀螺仪、手势）的功能必须在真机上测，Expo Go 和模拟器测不出来：用 Development Build。https://docs.expo.dev/develop/development-builds/introduction/
- 安卓真机：先开开发者选项和 USB 调试再插数据线，用 `npx expo run:android` 构建并安装。https://docs.expo.dev/develop/development-builds/create-a-build/
- iOS 真机：只能在装有 Xcode 的 Mac 上编译和签名，Windows 做不到；用 `npx expo run:ios --device`。https://developer.apple.com/xcode/ ｜ https://developer.apple.com/programs/
- iOS 选 Xcode 自动签名即可；免费 Apple ID 的开发签名约 7 天过期，且不支持远程推送这类需要苹果推送服务的能力。
- iOS 的原生依赖（通知、相册等）由 CocoaPods 准备，构建前跑 `pod install`。https://guides.cocoapods.org/using/getting-started.html
- 开发服务器（Metro）在跑时，改样式和业务逻辑保存后刷新手机即可生效，不必重新打包；只有新增原生依赖或改原生配置才重跑构建命令。https://github.com/facebook/metro ｜ https://reactnative.dev/

## 素材、音频与生成

- 需要环境音、白噪音这类素材：优先找带 CC0 声明的（可自由使用、修改、商用），下载前核对详情页授权协议；素材站以维基共享资源为例。https://commons.wikimedia.org/ ｜ https://creativecommons.org/publicdomain/zero/1.0/
- 素材来源格式不统一：用 ffmpeg 统一音频格式、处理循环点、统一响度；需要署名的素材把作者和来源链接记进项目的 `license.md`。https://ffmpeg.org/
- 项目需要成品背景音乐：交给专门的 AI 音乐模型生成，而不是让编程智能体用代码合成音频；例如火螺AI（MiniMax），其他音乐模型同理。https://hailuoai.com/music
- 写代码前要先确认界面长什么样：用一个前端审美类 Skill（如 Taste Skill，核心子技能 `design-taste-frontend`）按已定的规格和计划生成 HTML 原型。https://github.com/Leonxlnx/taste-skill

## AI 能力接入

- 项目要接入大模型：一律做统一封装，把调用方式、模型名、返回结构收敛在一层里，不绑死某一家接口，换厂商不重写业务逻辑。
  - 备注（课程里的实际做法，不建议照搬）：为了先跑通，开发阶段让客户端直连 DeepSeek，API Key 放在项目 `.env`。正式上线前仍须挪到服务端，Key 不进客户端。https://platform.deepseek.com/ ｜ https://api-docs.deepseek.com/
- 要把大模型调用挪到服务端又不想自建后端：用 Supabase 的 Edge Function，或 Expo Router 的 API Route。
- App 要做语音输入（说话转文字）：不要用系统自带语音识别，各机型支持的语种和能力差异极大，常见点了没反应；改用云端 ASR（Speech-to-Text），流程是录音→上传→拿回文字填进输入框。
- 语音输入还需要自动判断用户说的是哪种语言（不想提前指定语种）：选支持多语种自动识别的 ASR 模型，例如火山引擎豆包语音的 Seed-ASR。https://www.volcengine.com/docs/6561/2499930?lang=zh
- 用火山引擎的语音服务要注意：除了填 API Key，还要在控制台开通对应服务（如"录音文件识别 2.0"）并完成模型授权，否则有 Key、也重新打包了，仍拿不到识别结果；只改云端配置时不用重新打包。https://console.volcengine.com/
