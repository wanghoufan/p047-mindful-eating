# 122.i18n 国际化：让 App 支持多语言

## 本课总结

1. 上一节接入大模型后界面文字还只有英文，这一节推进Phase Six也就是i18n国际化，让同一个App能按用户选择的语言切换界面文字。
2. 用Spec Kit实现，Claude Code整理出98条需要国际化的文本，英文和西班牙语完整对齐，App名称Lura和问号这类图标字符保留不参与翻译。
3. 基础能力是App跟随系统语言显示，不支持的语言回退到默认英文；再补一个设置页面，让用户可以在中文、英文和西班牙语之间主动切换。
4. 真机测试切换三种语言：首页的呼吸和专注变成对应文字，AI生成的引导词也跟着界面语言一起切换，西班牙语同样正常。
5. 构建任务明明安装完成还在显示构建中，说明Claude卡在监控状态，直接告诉它当前进展，它就停止无效等待并结束监控任务。
6. 多语言资源放在RN App里src、i18n、resources目录下，英文中文西班牙分别对应en、zh、es的json文件，翻译不合适可以直接改对应文件。
7. 翻译文件就像一份翻译表，和页面文字一一对应；本阶段改动提交推送到GitHub，后续再推进App上架和商业化。

### 这一阶段要做什么

上一节我们给 App 接入了 AI 大模型，用户可以通过语音或文字描述自己的状态，再让大模型匹配合适的呼吸法。不过现在 App 里的界面文字还只有英文，为了让不同地区的用户都能用，这一节我们来推进 Phase Six，也就是国际化 i18n，给 App 加上多语言切换。这里的 i18n 是 Internationalization 的缩写，因为这个单词首尾字母中间正好有 18 个字母，所以写成 i18n。简单理解，就是让同一个 App 可以根据用户选择的语言，切换成对应的界面文字。

### 用 Spec Kit 完成多语言翻译

我们继续使用 Spec Kit 来实现这个阶段：新建一个 Claude Code 的会话，然后发送对应的指令。发送以后，Claude 会读取这个阶段的任务和现有国际化配置，然后开始补充多语言支持。因为 Phase Six 比较简单，Claude 也没有要我们确认的问题，很快就完成了。最后看一下输出的总结：Claude 一共整理了 98 条需要国际化的文本，英文和西班牙语已经完整对齐；像 App 名称 Lura 以及问号这类图标字符会保留，不参与翻译。

### 补一个设置页面

到这里，多语言的基础能力就做好了：App 可以读取手机的系统语言，如果系统语言是我们支持的语言，就自动显示对应版本；如果是其他还不支持的语言，就会回退到默认的英文。但现在语言跟着系统走，用户还不能在 App 里主动切换，所以接下来我们再补一个设置页面，让用户可以自己选择中文、英文或西班牙语。发送以后，Claude 会先问我们具体要支持哪些语言，现成的三个选项都不太完整，那我们选择 Other，手动指定中文、英文和西班牙语。确认以后，Claude 会开始补充设置页面和语言切换功能。最后从完成以后的总结可以看到，Claude 给首页新增了一个设置按钮，点击进入设置页面以后，用户就可以在中文、英文和西班牙语之间进行切换。

### 真机测试三种语言

接下来让 Claude 把最新版 App 安装到安卓手机上进行真机测试。发送以后，Claude 会先检查本地开发环境，再开始构建和安装，同时创建一个监控任务来跟踪进度。虽然电脑上一直显示构建中，但新版 App 已经安装到手机上了。那我们先直接测试：打开 App，就看到手机右上角新加了一个设置入口，点击进去就可以在中文、英文和西班牙语之间切换。我们先切换成中文，回到手机以后，Breathe 和 Focus 已经变成了呼吸和专注。进入呼吸，输入一个状态描述：我即将参加演讲，我有点紧张，再点击下面那个按钮进入呼吸引导页，这次匹配到的是平和呼吸法，AI 生成的引导词也是中文，说明界面文字和 AI 内容都已经跟着语言一起切换了。接着我们切换回英文，整个页面也会恢复成英文。因为英文前面测试的比较多了，那我们重点再看看西班牙语：选择 Español 以后，首页的呼吸和专注也会切换成对应的西班牙语；进入呼吸模式，随便选择一个状态进行匹配，可以看到呼吸法建议文字也都变成了西班牙语。到这里三种语言的切换基本没问题。

### 停掉无效的监控任务

回到 VS Code，会发现 Claude 还在等待构建任务结束，但其实 App 安装早就完成了，我们甚至都测试完了，那说明 Claude 目前卡在了监控状态这里。我们可以直接告诉它当前进展，停止无效等待。发送以后，Claude 就会重新确认当前状态，并且结束不再需要的监控任务。现在测试基本没问题了。

### 翻译文件放在哪里怎么改

那如果说你发现某些翻译不够合适，有两种改法：可以直接让 Claude 帮我们修改，也可以自己去改对应的多语言文件。如果想自己改的话，我们先问 Claude 这些文件放在哪里。发送以后，Claude 会告诉我们：多语言资源都放在 RN App 下 src 目录下 i18n 里面的 resources 这个目录下，英文对应 en.json，中文对应 zh.json，西班牙语对应 es.json。比如我们想改英文，就直接打开 en.json，会看到里面放了很多英文。那简单理解，我们可以把这个文件理解成一份英文翻译表：App 里每一句需要翻译的文字，都会在这里留一个固定的位置。比如这一段，它表达的意思其实很简单：Home 表示首页，Breathe 表示首页里的呼吸功能；在里面 Title 对应标题，所以显示的是 Breathe；Desc 对应下面的说明文字，所以显示的是 TheSquarePowerUVU 什么什么的。那也就是说，这个文件就是把 App 里的文案按照页面、功能、文字整理好了。那我们对照一下刚刚的 App 首页，就会发现这些内容和页面上的文字是一一对应的。那如果我们觉得某句翻译不合适，改起来也很简单：比如英文版本现在写的是 Title: Breathe，如果想把它换成别的英文，就直接改后面的 Breathe。中文和西班牙语也各自有一份相同结构的文件：我们打开中文文件，可以看到同一个位置写的是 Title: 呼吸，也就是说它们代表的是同一个标题，只是不同语言下显示的文字不一样；我们再打开西班牙语文件，也是同样的逻辑。所以 App 切换语言的本质，就是去对应的语言文件里找到同一个位置，再显示对应的翻译。

### 远程备份收尾

最后，我们还是把这个阶段的改动进行远程备份。和前面一样，直接让 Claude Code 帮我们完成 Git 提交和 GitHub 推送。发送以后，Claude 会整理当前改动，并且完成推送到远程仓库。那到目前为止，我们的 App 不仅跑通了核心功能，整体的产品体验也越来越完整。我们后续还会让 App 上架和商业化，进一步完成这个项目。我们下次见。
