# 114.怎么做 iPhone 真机实测？


## 本课总结

1. 本地运行 iOS App 需要一台装了 Xcode 的 Mac，iOS 的本地编译和签名都要通过 Xcode，Windows 无法完成。
2. iPhone 端要先信任此电脑，再从设置里打开开发者模式，从 iOS 16 开始不开这个就运行不了自建测试版。
3. npx expo run:ios --device 让 Expo 调用 Mac 上的 Xcode 编译 iOS 测试版并装到连接的 iPhone 上。
4. 首次构建常见三个问题：没有 iOS 文件夹、没设置 Bundle Identifier、电脑没装 CocoaPods，Claude Code 会带我们处理。
5. iOS 签名相当于苹果给 App 做身份验证，选自动签名即可，免费 Apple ID 能做真机测试，签名约七天后过期。
6. 还要到 Xcode 的 Apple Accounts 里用 Manage Certificates 创建 Apple Development 开发证书，本地通知能力要移除远程推送配置。
7. 安装后需在设置里信任开发者，再由电脑上的 Metro 实时提供页面；配好 Supabase 环境变量后真机开发环境就打通了。

---

前面我们了解到，有些功能只有真正装到手机上才能测出来。这一节我们一起来看怎么把测试版 App 安装到 iPhone 上，做一次完整的真机测试。首先需要知道的是，如果要在本地直接运行 iOS App，需要一台安装了 Xcode 的 Mac 电脑，因为 iOS 的本地编译和签名都要通过 Xcode 完成，Windows 系统的电脑没办法完成这一步。那如果你的 Mac 还没有安装 Xcode，可以回看前面的安装部分，从 App Store 下载后完成首次初始化，然后再继续下面的操作。

### 信任电脑并打开开发者模式

我们先用数据线把 iPhone 连接到 Mac，然后解锁手机。如果 iPhone 弹出要信任此电脑，选择信任，再输入锁屏密码确认。接下来还要打开开发者模式。从 iOS 16 开始，如果不开这个选项，iPhone 就不能运行我们自己构建的测试版 App。打开设置，在搜索框里搜索开发者模式，进入隐私与安全性里面的对应选项，然后把它打开。开启以后 iPhone 会要求重启，重启完之后再确认一次开启开发者模式就可以了。这个设置主要就是允许开发构建在手机上运行，不会影响日常使用。

### 开始构建：第一次常见的三个问题

手机连接好以后，我们打开要测试的 Expo 项目，再新建一个 Claude Code 会话，接下来把这段提示词发给他。

这里的 npx expo run:ios --device 简单理解，就是让 Expo 调用 Mac 上的 Xcode，把当前项目编译一个 iOS 测试版，并且安装到连接的 iPhone 上。iOS 第一次构建时经常还要处理一些苹果这边的配置，而且必须我们自己在 Xcode 里完成，所以提示词里也特意告诉 Claude Code：如果遇到签名之类的问题，先告诉我们怎么处理，不要直接往下跑。发送以后，Claude Code 会先检查设备和项目环境。首先它已经识别到了我们连接的 iPhone，接着又发现了几个第一次做 iOS 真机测试很常见的问题。

第一个是项目里还没有 iOS 文件夹。这个不用担心，第一次运行 expo run:ios 的时候，Expo 才会自动生成真正的 iOS 工程，也就是这个 iOS 文件夹，后面 Xcode 就会用这里面的文件来编译 App。第二个是还没有设置 Bundle Identifier。我们可以把它理解成 iOS App 的唯一编号，比如一个 App 可能使用类似 com 点某某点某某这样的格式，苹果后面做真机安装、签名甚至正式上架，都会通过这个编号来识别。第三个是电脑上还没有 CocoaPods。Xcode 负责把 App 编译出来，而 CocoaPods 主要负责准备项目需要的 iOS 原生依赖，比如我们用到通知、相册这类原生功能，对应的 iOS 代码就需要通过它来安装和配置。

### 签名方式与依赖安装

接下来 Claude Code 会带我们一步步处理这些问题。首先是 Bundle Identifier，这里我们用它推荐的就可以，后面有需要也能再调整，不用现在专门花时间想名字。接下来是 iOS 签名方式。我们可以把 iOS 签名理解成苹果给 App 加了一套身份验证，因为 iPhone 不能随便安装自己写的 App，所以安装之前系统要先确认这个 App 是谁开发的、它是哪一个 App，以及这台手机有没有权限装。这里面主要涉及开发证书、Bundle Identifier 和 Provisioning Profile，我们现在不用记这些名字，只需要知道它们共同决定了这个 App 能不能正常装到这台 iPhone 上。

Claude Code 给了我们自动签名和手动签名的两种方式，我们这里直接选择自动签名。Xcode 会根据登录的 Apple ID 自动帮我们处理证书和相关配置，对个人真机测试来说最省事。至于登录什么账号，我们直接用平时的免费 Apple ID 就可以做真机测试，不过这种开发签名通常大约七天后会过期，到时候就需要重新构建并且安装。如果你有付费的 Apple Developer 苹果开发者账号，就可以做长期测试，后面有 TestFlight 和正式上架时也会用到。

那接下来 Claude Code 会继续帮我们处理 CocoaPods 的安装。CocoaPods 安装完成以后，Claude Code 会开始生成 iOS 原生工程，并且把相关文件放到项目的 iOS 目录里。生成过程中它又发现我们刚刚设置的 Bundle Identifier 里带了小横线，而 iOS 的 Bundle Identifier 不支持这种写法。这个问题不大，直接让 Claude Code 帮我们改成符合要求的格式就可以。

修改完成以后又会进入原生依赖安装，也就是运行 pod install。这一步需要下载不少 iOS 相关的依赖，所以第一次执行通常会花一些时间。我这里安装到一半时因为网络问题，有部分依赖下载失败了，Claude Code 也就卡在这里。这种时候不用一直等，我们可以先中断当前任务，再让 Claude Code 重新执行 pod install，已经下载成功的部分通常不用重新来一次，它继续把剩下的依赖补齐。这次重新安装 pod install 就顺利很多了。中途如果遇到依赖解析或者下载失败也不用太慌，Claude Code 会根据报错继续排查，再把剩下的部分补上。等 pod install 安装完成，iOS 原生工程和依赖就准备好了。

不过真正把 App 装到 iPhone 之前，还要排查最后一步：配置 iOS 签名证书。这一步需要我们自己到 Xcode 里处理一次。

### 在 Xcode 里创建开发证书

证书准备好以后，Xcode 就知道这个 App 是谁开发的，也能自动帮我们处理当下 iPhone 真机测试需要的签名配置。接下来我们到 Xcode 里把开发签名证书准备好。先打开 Mac 上的 Xcode，然后点击左上角的 Xcode，进入菜单里的 Settings。进入设置以后来到 Apple Accounts，点击它登录自己的 Apple ID。登录完成以后点击自己的 Apple ID，下面会看到对应的 Team，如果是个人的话一般就是 Personal Team。进入以后点击 Manage Certificates，也就是证书管理。如果这里还是空的，就点击左下角的加号，选择 Apple Development，创建一个开发证书。创建完成以后，新的证书就会出现在列表里，这样 Xcode 这边的开发签名就准备好了。

### 构建中的两个签名问题

接下来可以回到 Claude Code 继续进行 iPhone 真机构建。回到 Claude Code，我们刚才签名证书已经准备好了，发送以后，Claude Code 会先检查 Mac 上是否已经有可用的开发证书，确认没问题后继续构建。构建过程中它又发现了一个签名问题：我们的项目用了 expo-notifications 来做提醒，但当前的 iOS 配置里还带上了远程推送相关的能力。帮我们区分一下两种通知。本地通知是 App 自己在手机上提前安排好的，比如用户设置晚上 10 点提醒，到了时间以后手机会自己弹出通知，不需要服务器参与。远程通知是服务器主动把消息推到用户手机上，比如新闻 App 的突发新闻、微信的新消息，这类通知需要通过苹果的推送服务发送。我们这个项目目前只需要本地通知，但 expo-notifications 的配置里把远程推送能力带上了。免费 Apple ID 可以做基础的真机测试，但不能用这里需要苹果服务器授权的远程推送能力，所以签名会失败。Claude Code 排查到原因以后，就会把远程推送相关的配置去掉，只保留本地通知，这样不会影响我们现在的提醒功能，也可以继续使用免费的 Apple ID 做真机测试。

继续构建的时候，Mac 还可能弹出钥匙串密码窗口。这是因为 Xcode 正在用我们刚刚创建的开发证书给 App 签名，而证书对应的私钥保存在 Mac 的钥匙串里，所以系统需要我们确认这次使用是允许的。这里输入 Mac 的登录密码，然后点击允许就可以。如果不想以后每次构建都重复确认，也可以选择始终允许。

继续构建以后，App 编译和签名成功了，不过安装到 iPhone 时又遇到了一个问题：iPhone 不仅会检查 App 本身，还会检查 App 里面一起打包进去的原生框架。Claude Code 发现有一个叫 Hermes 的框架没有正确签名，所以暂时不能安装。但不用着急，Claude Code 会根据报错继续调整签名配置，处理完成之后，App 就会成功安装到 iPhone 上。

### 信任开发者并接上开发服务器

这时候桌面上已经能看到我们的 App 了，但第一次点开，iPhone 会提示未受信任的开发者，所以还不能直接运行。那么我们打开手机的设置，进入通用，再找到 VPN 与设备管理，在这里也可以看到刚刚安装的开发者 App 以及对应的未受信任提示。点进去以后选择信任并且确认允许，完成之后回到桌面再次点击 App，这次 App 就可以正常启动了。

不过第一次进去以后，没有直接看到我们写的页面，而是进入了这么一个页面。这是啥玩意？是我们打包出问题了吗？其实不是。这是因为我们安装的是 Development Build，可以理解成装在 iPhone 上的测试版 App，而我们平时看到的页面功能和样式，会由电脑上的 Metro 开发服务器实时发送给它。这样做的好处是，不用每次都重新编译、签名和安装 App，刷新一下就能看到最新效果。这里点击 Next，如果 iPhone 弹出允许访问本地网络，记得选择允许，这样手机才能找到同一网络下 Mac 上运行的 Metro。接着回到 Claude Code，让它启动开发服务器。

### 遇到运行时报错怎么办

发送以后，Claude Code 会启动 Metro，并且保持运行。这时候再回到 iPhone 打开 App，页面虽然加载出来了，但还是出现了一段运行时报错。遇到这种情况，只要把报错信息复制给 Claude Code 就可以。对你最关键的是上面那条 reference error，property message doesn't exist；我们也可以把下面完整的报错堆栈一起复制过去，让 Claude Code 更容易定位。Claude Code 一排查就发现，问题还是出在 Hermes。前面为了先让 App 能安装到手机上，我们临时调整过相关配置，所以虽然安装成功了，但真正运行时又出现了连接问题。这次 Claude Code 会把配置重新调整，和 Expo 默认版本对齐，再处理签名问题。

### 打通之后的最后一个配置

修复完成以后，我们的 iPhone 真机开发环境就基本打通了。接下来还差最后一个配置，就是把 Supabase 的连接信息补上。Claude Code 提示我们需要两个环境变量：一个是 Supabase 的项目 URL，另一个是 Public Key。我们把之前项目里用到的这两个配置提供给 Claude Code，让它写进项目的配置文件里。配置完成以后，Claude Code 会重新启动 Metro，让 App 读取最新的环境变量。我们再简单检查一下几个主要页面，比如提醒页面，可以让它打开连接；历史、设置这些页面也没有问题。所以现在 Development Build 安装就算完成了。

后面我们如果只是修改页面样式或者业务逻辑，只要电脑上的 Metro 保持运行，改完代码以后回到手机刷新就能直接看到最新效果，不需要每次重新打包。只有新增原生依赖或 App 配置这类操作，才需要重新运行命令 npx expo run:ios --device。如果用的是免费 Apple ID，还要记得开发签名通常七天会过期，到时候我们重新构建并安装一次就可以继续测试了。我们下期见。
