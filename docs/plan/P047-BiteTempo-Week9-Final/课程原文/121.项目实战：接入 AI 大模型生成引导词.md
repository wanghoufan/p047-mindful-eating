# 121.项目实战：接入 AI 大模型生成引导词

## 本课总结

1. 第五阶段接入AI大模型完善Breathe输入页面，语音先转文字再交给大模型判断呼吸法并生成引导词，共七个任务对应T030到T036并同步标记进度。
2. 测试前在项目的.env文件里配置DeepSeek的API Key，开发阶段先客户端直连，正式上线前要改用云端调用避免密钥暴露在App里。
3. 文字输入与呼吸法匹配基本跑通：焦虑、状态不对劲、低能量分别匹配4-7-8、长呼气、平衡呼吸法，但引导词文案还比较通用。
4. 系统自带语音识别在中文设备上直接退出，Claude Code加了兜底处理，最终决定接入云端STT，再改用豆包语音Seed-ASR支持自动识别语种。
5. 修复把每种呼吸法的特点和状态标签一起给AI做匹配，引导词也适配多语言，App界面是什么语言模型就返回什么语言的引导词。
6. 火山引擎的API Key填进项目后重新打包，还要在控制台开通录音文件识别2.0服务并完成模型授权，语音才真正转成文字。
7. 真机用英语说演讲前紧张，App转成文字推荐Box Breathing并生成契合状态的引导词，整个流程跑通后推送到GitHub保存版本。

---

### 第五阶段目标

接下来继续推进 Phase Five，进入我们熟悉的 AI 大模型接入。主要目标是完善 Breathe 的输入页面：让用户既可以输入文字，也可以通过语音说出自己当前的感受；语音会先转换成文字，再把用户输入发送给模型；由模型判断更适合哪一种呼吸法，并且生成对应的引导词，最后交给呼吸页面进行展示。这里我们继续使用 Spec Kit 的实现流程：先新建一个 Claude Code 的会话，然后让它实现 Phase Five。发送以后，Claude Code 还是会先读取和这个阶段相关的资料以及现有代码，确认前面的技术约束和数据格式；接下来它还会检查这次要接入的语音识别方案，以及现有 AI 接入层应该怎么用。确认以后正式开始修改代码。Phase Five 一共有 7 个任务，对应 tasks.md 里的 T030 到 T036，Claude Code 每完成一个任务也会在里面同步标记，这样我们可以直接看到当前进度。全部完成以后，这个阶段的核心功能就搭起来了：用户的文字或者语音内容会交给大模型分析，再匹配合适的呼吸法，并且生成对应的呼吸引导语。

### 真机测试前的准备

接下来我们就可以进入真机测试，重点验证语音输入、文字识别、DeepSeek 匹配和呼吸引导这条完整链路。这里先让 Claude Code 简单说明测试步骤，同时重新构建一个安卓测试版本。发送以后，它会先整理这个阶段的测试流程，再开始安卓构建，我们等它完成。构建完成以后可以看到，APK 已经成功生成并且安装到了连接的安卓手机上，开发服务也已经正常启动。接下来主要测试三件事：文字输入能不能正常调用 AI，语音能不能正确转成文字，以及匹配到呼吸法以后能不能顺利进入呼吸引导页面。正式测试之前，我们还要先配置 DeepSeek 的 API Key。点开 VS Code 左上角的资源管理器，展开 RN App 文件夹，可以看到项目里已经有一个 .env 文件；打开以后找到 DeepSeek API Key 对应的字段，把我们之前申请好的 API Key 粘贴到等号后面，然后保存。这里也提醒一下：目前还处于开发和测试阶段，所以我们先采用客户端直连 DeepSeek；正式上线之前，还是要用 Claude Code 把大模型调用改到云端，避免 API Key 暴露在 App 里。

### 语音识别先出问题

配置完成以后就可以回到手机上，开始测试这个阶段的完整流程了。点击进入 Breathe 模式，这里已经有了语音按钮，我们先测试一下语音。第一次点击麦克风，App 会请求麦克风权限，说明麦克风调用已经接通了；不过实际讲话以后，页面没有把语音转成文字，所以语音识别这部分还有点问题。那我们就先测试文字输入和呼吸法匹配：先选择 Anxious，也就是焦虑状态，App 给我们匹配了带有停顿和较长呼气的 4-7-8 呼吸法；随后再换成 Weird，表示感觉状态不太对劲，这次匹配到的是长呼气呼吸法，引导语是把节奏放慢下来；最后再试一个 Low Energy，低能量状态，匹配出来的是更均匀的平衡呼吸法。那这部分逻辑已经基本跑通了。不过也能注意到，呼吸引导词的文案看起来比较通用，没有明显结合用户输入的状态。所以接下来我们要排查两个部分：语音识别为什么没有生效，以及 AI 到底是怎么匹配呼吸法和生成引导词的。这里我们直接把这几个问题一起发给 Claude Code。

### 排查语音识别与匹配逻辑

发送以后，Claude Code 会先检查语音识别的实现和 AI 匹配逻辑，我们等它排查。语音识别的问题很快就定位到了：我们现在用的是手机系统自带的语音识别服务，我的这台设备在识别中文时返回了不支持当前语音，所以语音识别刚启动就直接退出了，这也是为什么输入框只会闪一下。之后 Claude Code 给我们增加了兜底处理：会先检查手机支持哪些识别语音，如果当前语音不能用，就自动换成设备支持的语音；如果还是不行，也会直接提示用户，而不是像之前一样点了没反应。不过这还不算彻底解决，因为不同安卓手机自带的语音识别能力差异比较大，如果想让语音识别在不同设备上都更稳定，我们后面还是要接入统一的云端语音识别服务。另外，Claude Code 也帮我们检查了呼吸法的匹配逻辑：我们 App 里一共有六种呼吸法，之前虽然会让 DeepSeek 来选，但只告诉了它呼吸法的 ID，没有告诉它每种呼吸法的特点，所以有点像让 AI 盲选。现在 Claude Code 把每种呼吸法对应的特点和状态标签也一起提供给 AI，它就可以根据用户输入来做更合理的匹配。另外，引导词本来也是由 AI 生成的，但之前 App 没有把这部分内容用起来，这次也一起修复了。现在 AI 返回的呼吸法和引导词都会正常显示到后面的呼吸页面。

### 验证修复与三个遗留问题

我们再回到 App 看看修复后的效果。进入 Breathe，点击语音按钮，App 这次给出了功能不可用的提示；那我们继续选择 Anxious，也就是焦虑，进入呼吸页面后，现在已经能看到 DeepSeek 根据当前状态生成的引导词，比如"慢慢来，让呼吸带你回到平静"。再返回输入页换成 Low Energy，这次的引导词也会跟着变化，说明 AI 生成的内容已经正常传到呼吸页面。但这里也存在一个问题：引导词会同时显示中英文，而更合理的方式是 App 当前是什么语言，大模型就直接返回什么语言的引导词。另外，我们点击 End Session 以后，页面虽然回到了输入页，但一直卡在 Find your rhythm，说明加载状态没有正确地重置。而且目前语音输入还是不能正常用，得让 Claude Code 给出一个真正可行的解决方案，而不是只弹一个提示。所以我们把这三个问题一起交给 Claude Code。

### 多语言适配与云端 STT

发送以后，Claude Code 会继续排查这三个问题。稍等片刻后，首先是引导词的多语言适配：现在 App 会把当前使用的语言一起传给 DeepSeek，比如当前是英文就要求模型返回英文引导词，是中文就返回中文，这样引导词就能和 App 的界面语言保持一致。第二个是退出呼吸后卡在 Find your rhythm 的问题，这个比较简单，是返回输入页时加载状态没有重置，Claude Code 已经帮我们修复了。前两项改完可以直接在 App 上验证，比较麻烦的还是第三项。Claude Code 排查后发现，手机系统自带的语音识别不稳定，不同设备的支持情况差异很大，所以它给出几个方案：要么接入云端 STT，要么在不支持的设备上直接关闭语音功能，或者继续尝试系统自带的语音识别。既然我们就是希望用户能正常用语音输入，那最稳妥的还是第一种，接入云端 STT。STT 就是 Speech-to-Text，语音转文字，用户说话以后 App 把录音交给云端识别：用户点击麦克风开始录音，再次点击结束，App 把录音发送到火山引擎，之后再把文字填回输入框。

### 换用豆包 Seed-ASR 自动识别语种

这里还有个问题：Claude Code 当前的方案指定了中文普通话，但我们的 App 面向海外用户，更合理的做法应该是自动识别用户说的语言。所以这里继续让 Claude Code 找一下火山引擎支持自动识别语种的方案。发送以后，Claude 会去找适合的多语言识别能力。它调研后发现，我们现在用的语音识别方案需要提前指定语种，比如中文和英文要分别调用不同的模型；如果想让系统自己判断用户说的是哪种语言，可以改用豆包语音的 Seed-ASR，让模型自动处理多语言识别。Claude 这里也给出了官方文档链接，不过他没办法直接读取这个动态网页里的完整内容，需要我们手动把关键识别内容提供给他。那么点击会话里的文档链接，浏览器会打开火山引擎的语音识别官方文档，在文档里可以看到接口的请求示例，我们先点击复制，把它粘贴到 Claude 里，然后再找到下面的返回示例也复制进去。把这段官方内容发送给 Claude 以后，它就能根据真实接口调整实现。我们等它完成修改，修改后 App 就可以直接让语音识别服务自动判断语种，再把结果转换成文字。

### 配置火山引擎 Key 重新打包

那接下来我们需要把火山引擎语音识别的 API Key 配置到项目里，然后重新打个测试包。回到刚才的火山引擎语音文档，点击跳转到控制台 API Key 管理的链接，这里可以专门给这个 App 创建一个新的 API Key。创建完成以后点击复制，再回到 VS Code：点击左上角的资源管理器图标，打开 RN App 目录下的 .env 文件，把 API Key 填到 EXPO_PUBLIC_VOLC_ENGINE_API_KEY 对应的位置并保存。配置完成以后回到 Claude Code，让它重新打包。发送以后，它会重新构建安卓测试版本并且安装到手机上。打包完成，我们就可以回到 App 里测试新的语音识别功能了。进入 Breathe 模式，点击麦克风以后，这次已经可以正常显示 Listening 状态，说明录音这一步没问题；我们说一句测试，然后再次点击麦克风停止录音，但是停止以后，识别结果还是没有显示出来。下面我们回到 Claude Code，把当前的现象告诉它。发送以后，它会继续检查录音结果、音频格式和返回内容，排查下来发现录音文件、音频格式和网络都没问题，但当前账号还没有开通豆包语音识别大模型对应的资源权限。

### 开通服务后全流程跑通

那么接下来回到火山引擎控制台，点击左侧的开通管理，找到录音文件识别 2.0 相关的服务，点击右侧的开通按钮，再完成模型授权。因为这次只是开通云端服务，没有修改代码，所以不需要重新打包，我们直接回到 App 测试就可以了。重新进入 Breathe，这次我们用英语试一下语音输入，然后再次点击麦克风结束录音，可以看到这次语音已经成功转换成文字了。接着点击匹配呼吸法，App 推荐的是 Box Breathing，而且这次的引导词已经明显契合刚才的输入：因为我们提到马上要演讲、很紧张，所以它会鼓励我们先稳定下来，用更平稳的呼吸节奏，并且在引导语里提醒保持冷静的状态。这说明现在整个流程已经跑通了：用户说话以后，App 能把语音转换成文字，再交给 AI 判断当前状态，匹配合适的呼吸法，并且生成对应的引导词。最后我们还是把这个阶段的代码改动推送到 GitHub，保存当前版本。发送以后，Claude 会整理当前改动并且完成提交和推送。这样 Phase Five 的开发和测试就告一段落了，我们下期见。
