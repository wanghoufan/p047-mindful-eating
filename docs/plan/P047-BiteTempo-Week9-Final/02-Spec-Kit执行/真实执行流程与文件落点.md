## 1. Human Gate 之前：创建正式文档

依照 P047 已生效 ORCA 计划阶段规范，用户已确认产品需求，并已明确选择 C「慢食刻 / BiteTempo」视觉与品牌。以下命令在已安装 Spec Kit 的客户端中**真实触发**；如果当前集成是 Skills 而非斜杠，以其官方等价调用方式执行，留下命令或 Skill 执行证据。

1. `/speckit.constitution`：生成项目级 ` .specify/memory/constitution.md`。纳入：用户范围、代码/版权、原型视觉、音频 ASR 限制、AI 只能润色、BYOK 与安全、离线核心、主题语言、真机验收、用户原有 ORCA 治理优先级。不要制造第二套互相冲突的宪法；有冲突返回项目生效规则裁决。
2. `/speckit.specify`：读取本包 P047 产品需求输入，创建 `specs/001-mindful-meal-journal/spec.md`；说明目标、用户故事、FR、结果、错误路径、验收标准；不在 SPEC 偷写 implementation 框架细节。
3. `/speckit.clarify`：核对已确认事实，只就真正未决、不可从文档推断的地方询问。不得反复追问已经确定的“安卓/两 Tab/系统语音/DeepSeek 润色”等。
4. `/speckit.plan`：根据 SPEC 写 `plan.md`、`research.md`、`data-model.md`、`quickstart.md` 等适用文件；用当前 Expo/React Native 官方兼容矩阵，实际检查本地 SDK、包版本。**AI Provider 与系统 ASR 属不同层。**
5. `/speckit.checklist`：创建需求完整度检查（工具版本若不同，查看帮助后采用其当前支持方式）。
6. `/speckit.tasks`：创建分期 `tasks.md`，每个任务含可验收结果、依赖与文件路径，见本包《任务计划建议》但不要机械照抄任务编号。
7. `/speckit.analyze`：跨文档核对 Constitution → SPEC → PLAN → TASKS，特别对照已冻结 C 原型、下方无声自动短句轮播（无下一句按钮）、语音不可用、密钥泄露、时钟恢复、主题语言与品牌资产。出现 P0/阻塞矛盾先修改，再运行 Analyze。

**ORCA 管理**：P047 已铺包，按 AGENTS 当前版本由正规阶段执行自审/QA 留痕；允许单智能体模式但不伪造独立 Reviewer。角色分工与 Gate 不因课程而改变。开发批准**必须由用户真正授权**；示例 `第二阶段，开发` 是现有 ORCA 的阶段口令。

## 2. Human Gate 之后：开发和收敛

1. `/speckit.implement`：按任务分组小批次真实实施；可多次调用，不要求一次超长会话跑到底。用户批准开发后可以自动连续修复到全部 TASK 结束。
2. 生成可运行第一个骨架后立即做 `npx expo run:android` 开发测试版真机安装（具体本机依赖先检查）；后面每个关键里程碑复测。
3. 实测系统语音识别：设备可用性、中文、权限、超时、兜底；不能因为课程中系统识别曾失败，就暗中换第三方 ASR。
4. AI 文本润色：配置个人 Key 在 SecureStore，真实测试 DeepSeek API。没有测试凭证时要明确标“受凭证阻断”，不可假定接口成功。
5. 逐批执行 `/speckit.converge`：对照规格检查缺口，必要时追加 task→重新 `/speckit.implement`→再次 `/speckit.converge` 直到真实闭环。官方参考：https://github.com/github/spec-kit/blob/main/docs/guides/evolving-specs.md
6. QA 真机功能/安全/截图复验 + 关键 AC 跟踪矩阵落盘；首次发布用户签收（现有 ORCA Gate）。
7. 禁止未经用户本人许可自动 commit/push / 发布商店 / 写生产密钥 / 删除原仓库内容。课程提到 Git 推送是教学动作，实际服从当前授权边界。
