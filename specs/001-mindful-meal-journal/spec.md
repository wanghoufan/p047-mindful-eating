# Feature Specification: 慢食刻 / BiteTempo · 正念用餐与语音心得

**Feature Branch**: `001-mindful-meal-journal`

**Created**: 2026-10-11

**Status**: Ready for planning

**Input**: 用户已确认的 P047 产品需求（用餐计时 + 静音文字提醒 + 语音心得 + AI 去口水词整理；品牌 C「慢食刻 / BiteTempo」；安卓首发）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用餐计时与慢食提醒 (Priority: P1)

用户打开 APP，在「用餐」页选择目标时长（10/12/15/20 分钟），点「开始用餐」。一个柔和的光球缓慢呼吸，总时间倒计时，**倒计时下方始终只显示一句温和的文字提醒**，并按可设置的间隔**自动无声切换**。用户可随时暂停、继续、提前结束；到达目标时间时显示「目标时间已到」，但不强制结束，也不发声。

**Why this priority**: 这是产品存在的核心理由——帮助用户放慢进食；单独实现它就是一个可用的 MVP。

**Independent Test**: 在真机上选择时长并开始计时，观察倒计时与文字自动切换；暂停后倒计时与文字均冻结；继续后按剩余时间恢复；全程无任何声音或振动。

**Acceptance Scenarios**:

1. **Given** 首次打开且未开始，**When** 查看用餐页，**Then** 显示默认 10:00、光球与开始按钮，且下方已有一句静态文字提醒。
2. **Given** 未开始，**When** 依次选择 12/15/20 分钟，**Then** 倒计时初始值准确更新且不误倒数。
3. **Given** 计时进行中，**When** 暂停再继续，**Then** 暂停期间时间与文字都冻结，继续后从剩余时间恢复且不跳回初始值。
4. **Given** 计时进行中，**When** 离开前台若干秒后返回，**Then** 时间按实际经过时间还原，不重复倒数、不变快。
5. **Given** 计时进行中，**When** 跨越提醒间隔，**Then** 下方文字每次只显示一句并自动淡入切换；**没有下一句按钮、没有声音、没有 TTS、没有振动**。
6. **Given** 计时进行中，**When** 点「提前结束」，**Then** 出现确认；取消不结束，确认则记录本次实际秒数。
7. **Given** 到达 0:00，**Then** 显示「目标时间已到」，不出现负计时，用户可自行结束。

---

### User Story 2 - 语音心得与 AI 文字整理 (Priority: P1)

用户切到「心得」页，点「AI 语音记录」，用手机**自带系统语音识别**口述心得；识别结果落入可编辑的原文区。用户点「AI 整理」，系统调用 DeepSeek **只删除口水词、修复语病与标点**，给出整理结果并与原文对照；用户可编辑、可保留原文、可重试，确认后保存为心得。历史心得可查看、编辑、删除。

**Why this priority**: 这是与纯计时工具的核心差异——把「打字的麻烦」变成「说出来」，并留下可回看的个人记录。

**Independent Test**: 真机口述一段含口水话的中文，观察原文落入输入框；触发「AI 整理」，核对结果只变通顺、未添加建议或改变事实；保存后历史出现记录；删除需确认且只删一条。

**Acceptance Scenarios**:

1. **Given** 在心得页，**When** 点「AI 语音记录」，**Then** 系统语音能力可用时启动识别；不可用、被拒权限、无结果或超时**都必须清楚提示并可回退**，绝不静默无响应。
2. **Given** 完成一次口述，**When** 识别结束，**Then** 文字准确落入原文区且可编辑，原始内容不丢。
3. **Given** 已有原文，**When** 触发 AI 整理，**Then** 结果只去口水词/修语病标点，**不出现饮食建议、原因判断或虚构事实**，且保留第一人称、时间、否定词与关键方法。
4. **Given** 无网络/无 Key/额度不足/权限失败，**When** 触发整理或语音，**Then** 错误反馈清楚，草稿仍可编辑与保存。
5. **Given** 系统语音不可用，**When** 用户改用键盘语音或手动输入，**Then** 流程同样可用，且不强制 AI 成功。
6. **Given** 已有历史心得，**When** 查看/编辑/删除，**Then** 持久化正确，删除须确认且仅作用一条。

---

### User Story 3 - 主题、语言与设置持久化 (Priority: P2)

用户可在设置中切换外观（浅色/深色/跟随系统）、语言（跟随系统/简体中文/English）与提醒间隔（默认 60 秒，可选 30/90/120 秒或关闭）以及动画减弱；并可在设置中填入自己的 DeepSeek API Key。所有设置与当前计时/输入状态在切换与重启后保持。

**Why this priority**: 让产品适配用户环境并长期可用；不影响核心任务，但属必要的可用性基线。

**Independent Test**: 切换主题与语言、改提醒间隔、重启 APP，核对设置保留且切换过程中计时与草稿都不丢。

**Acceptance Scenarios**:

1. **Given** 默认跟随系统，**When** 系统切换深/浅色，**Then** APP 跟随更新；手动选择后以自己的选择为准。
2. **Given** 中文界面，**When** 切到 English，**Then** 文案切换正确、无溢出，计时与草稿不丢。
3. **Given** 设置已修改，**When** 重启 APP，**Then** 设置仍为用户所选。

---

### Edge Cases

- 系统语音：无权限、无识别服务、语言不支持、多次回调、重复停止、来电或系统打断、切前后台 → 最终只填入一次，不截断/不丢字/不重复追加；不保留音频文件。
- 计时：手动修改系统时间、设备睡眠、锁屏、切后台 → 按单调时间恢复，避免倒退或加速。
- AI：返回空串、返回建议、变更数字/事实、返回执行指令 → 拒绝或要求人工校对；失败不抹草稿。
- 网络/额度：断网、401、429、超时、余额不足 → 可读错误，可重试，不泄漏 Key。
- 数据：重复点击整理/保存不产生重复记录；未保存草稿被系统中断后可找回。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供两个主 Tab「用餐」「心得」；设置入口置于顶部，**不得**作为第三个 Tab。
- **FR-002**: 用餐页 MUST 提供 10/12/15/20 分钟预设，默认 10 分钟并记忆上次选择。
- **FR-003**: 计时状态 MUST 覆盖 `未开始 → 进行中 ↔ 已暂停 → 完成/提前结束`，且切后台/锁屏后按实际经过时间纠正。
- **FR-004**: 用餐过程 MUST 展示柔和循环光球动画，避免剧烈闪烁；MUST 支持动画减弱。
- **FR-005**: 倒计时正下方 MUST 始终只显示一句文字提醒，并按可设置间隔**自动无声**轮播（默认 60 秒，可设 30/90/120 秒或关闭）；MUST NOT 提供下一句按钮、TTS、提示音、背景音乐或振动。
- **FR-006**: 用户 MUST 能随时暂停、继续、提前结束；提前结束 MUST 确认；到达目标时间 MUST 提示但不强制结束、不出现负计时。
- **FR-007**: 系统 MUST 本地保存每次会话的目标、实际用餐秒数、日期与完成状态；MUST NOT 存储音频。
- **FR-008**: 心得 MUST 支持点击「AI 语音记录」发起**系统语音识别**并把结果落入可编辑原文区。
- **FR-009**: 系统在语音无权限/无服务/语言不支持/超时/取消/失败时 MUST 清楚提示并允许**键盘语音或手动输入**，且不得丢失已有文字；MUST NOT 自行接入第三方 ASR 云服务。
- **FR-010**: 系统 MUST 通过统一文本整理接口调用 AI，仅整理用户原文：删除口水词/重复、修复标点与轻微语病，保留第一人称、事实、情绪、时间与方法；MUST NOT 添加未说出的分析、建议、诊断或评价。
- **FR-011**: 整理前 MUST 自动保存原文草稿；整理结果 MUST 与原文对照，允许修改、重试、保留原文、取消，用户确认后才写为最终心得。
- **FR-012**: 心得 MUST 支持新增/查看/编辑/删除并本地持久化，无网络也可浏览；删除 MUST 确认且针对单条。
- **FR-013**: DeepSeek MUST 采用用户自填 API Key（BYOK），安全存储并可清除；无 Key 时 MUST 提示输入并允许原文保存；Key MUST NOT 硬编码、日志打印、进入 HTML、`EXPO_PUBLIC_*` 或 Git。
- **FR-014**: 品牌 MUST 采用冻结的 C「慢食刻 / BiteTempo」；主题 MUST 支持 LIGHT/DARK/SYSTEM（默认 SYSTEM）；语言 MUST 支持 zh-CN/en/FOLLOW_SYSTEM（默认跟随系统）；设置 MUST 持久化；切换 MUST NOT 丢计时与录入文本；不支持的系统语言 MUST 回退 zh-CN。
- **FR-015**: 计时、光球、文字提醒、心得编辑与浏览 MUST 离线可用；AI 整理 MAY 需要网络与有效凭证；系统语音识别离线能力 MUST NOT 被承诺为必然。
- **FR-016**: 产品 MUST 能在安卓真机安装运行，并产出可独立打开、断网可用的安装包。

### Key Entities *(include if feature involves data)*

- **MealSession（用餐会话）**: 目标时长、实际用餐秒数、起止时间戳、结束原因（到时/提前结束）、创建时间。
- **MealNote（心得）**: 原文、最终文本、修订号、可选关联会话、是否经 AI 整理、创建/更新时间。
- **LocalSettings（本地设置）**: 默认时长、主题模式、语言模式、提醒是否开启、提醒间隔秒数、是否减弱动画。
- **ProviderConfig（AI 服务配置）**: 服务提供方标识、模型标识、传输方式；API Key 仅存于安全存储，不入普通数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在 2 次点击内从主页开始一次用餐计时（选时长 → 开始）。
- **SC-002**: 100% 的用餐计时会话全程无声音、无振动、无语音播报（仅屏幕文字）。
- **SC-003**: 计时在切后台/锁屏返回后，误差控制在数秒级且不出现倒退或加速。
- **SC-004**: AI 整理后，原话中的否定词、数字、时间与关键方法 100% 保留（黄金样例集全部通过）。
- **SC-005**: 语音不可用或 AI 失败时，用户在 1 步内仍能手动保存原文，草稿零丢失。
- **SC-006**: 用户能在 1 次操作内完成主题或语言切换，且切换后计时与输入不丢。
- **SC-007**: 首次使用的用户无需外部讲解即可完成「计时 → 口述 → 保存」完整流程。

## Assumptions

- 目标用户为个人安卓用户，首版单用户本地使用，不做账号与云同步。
- 手机具备 Android 系统语音识别能力或可回退键盘语音/手动输入（兼容性由真机验证）。
- 用户自行提供有效的 DeepSeek API Key 用于 AI 整理；无 Key 时该项标记为受阻而不影响核心功能。
- 系统语音的提供方可能联网，产品不承诺纯离线语音。
- 首版仅做中文与英文 UI 文案，架构预留后续语言扩展。

## Clarifications

### Session 2026-10-11

需求来源为用户已确认的 P047 交接包 V1.3。以下关键点在需求阶段即已确定，**不重复追问**：

- 平台：安卓首发，React Native + Expo（原生系统语音能力所需）。
- 导航：底部两 Tab（用餐/心得）+ 顶部设置入口，不做第三 Tab。
- 语音输入：Android 本机系统语音识别，**不接第三方 ASR**。
- AI：统一文本整理接口，首版 DeepSeek，**只去口水词/修语病标点**，不分析不评价。
- 密钥：个人 BYOK，存 SecureStore；禁止进入代码/日志/Git/`EXPO_PUBLIC_*`。
- 提醒：倒计时下方**自动无声文字轮播**，无下一句按钮、无声音/振动/TTS。
- 云：不做账号、云同步、云数据库。
