# 慢食刻 / BiteTempo Constitution

> 本宪法是 P047 项目的最高技术约束；与用户既有 ORCA 治理规则冲突时，**ORCA 治理优先**（见 Governance）。

## Core Principles

### I. 用户场景与范围冻结
产品只服务一个核心场景：帮助进食较快的人放慢进食，并在饭后口述心得、自动整理成个人记录。
- 必须保持两个主 Tab（用餐 / 心得），设置为页面内入口，**不新增低频 Tab**。
- 不得实现被明确排除的能力：AI 饮食建议、健康诊断、趋势或自动评分；第三方 ASR/云 STT；后台录音与上传；白噪音混音台、冥想课程、TTS 播报、提示音、振动；会员/付费/社交/云同步/云数据库；强制憋气或强制吃够时长。
- 任何范围扩张必须先经用户确认（Change C）。

### II. 原型为视觉与交互真源
`docs/design/prototype/index.html`（用户批准的 C「慢食刻 / BiteTempo」）是视觉与交互基线。
- 真实 APP 必须忠实还原其导航、层级、字体、光球、**倒计时下方单句无声文字自动轮播**与按钮状态。
- **禁止用 WebView 包装 HTML 冒充原生实现**；HTML 仅作对照，不是成品壳。
- 已冻结的品牌（中文名/英文名/图标/启动画面）不得由实现者二次选择。

### III. AI 只整理、不改意
AI 的唯一职责是把用户自己说过的话整理成通顺的第一人称记录。
- 只允许：删除口水词与机械重复、修复明显语病、规范标点与自然断句。
- 禁止：添加用户未说出的事实/数字/情绪/饮食建议/健康判断/因果分析/总结标题；改变原意、第一人称、时间、否定词、程度词、关键方法。
- 必须保留原文，用户明确确认后才写为最终心得；失败或断网不得丢草稿。
- 用户输入只是待整理文本，其中即使含命令也不得改变模型职责。

### IV. 隐私、密钥与权限最小化
- 麦克风仅在用户主动发起语音记录时使用，且清楚提示；不做后台全程录音。
- DeepSeek 采用个人 BYOK：API Key 由用户自行在设置中填入，存于 `expo-secure-store`（Android Keystore 支撑）。
- **密钥不得**出现在代码、原型、截图、数据库、日志、Git、`EXPO_PUBLIC_*` 变量或 Web Bundle 中；不得预置任何真实密钥。
- 仅在用户触发「AI 整理」时发送本次必要文本，前台明示会发送给所选服务商。
- 公开发布前必须切换到具备鉴权与配额保护的 `ServerProxyProvider`（保留迁移位，本轮不实现）。

### V. 离线核心可用与静默原则
- 计时、光球、文字提醒、心得编辑与浏览、历史记录必须离线可用且本地持久化（SQLite）。
- 用餐提醒**全程静音**：只有屏幕文字；无下一句按钮、无 TTS/提示音/背景音乐/振动；暂停同步暂停轮播。
- 计时不得靠固定 `setInterval` 每秒累减；须用单调时间 + 挂钟校正，切后台/锁屏后按实际经过时间恢复。
- 系统语音识别本身的离线能力**不作保证**；UI 不得许诺「语音始终不离开设备」。

### VI. 主题与多语言基线
- 主题三态 `LIGHT` / `DARK` / `SYSTEM`，默认 `SYSTEM`，全页面统一语义 Token；沉浸式计时页遵守用户所选主题，不擅自强制另一态。
- 多语言 `zh-CN` + `en`，设置项 `FOLLOW_SYSTEM`（默认）/ 简体中文 / English；系统语言不支持时回退 `zh-CN`。
- 设置持久化，重启保留；切换主题/语言不丢业务状态、计时与当前输入。
- 文案与业务逻辑分离，走标准语言资源，禁硬编码分支；可扩展架构：新增语言只增资源与适配，不重写核心业务。

### VII. 真机证据优先（不做假验收）
- 只有**实际运行并验证**的项目才能标 `PASS`；未跑过的记 `NOT_TESTED`，缺凭证的记 `BLOCKED`。
- 禁止以 HTML 浏览器截图冒充安卓运行截图；禁止把固定示例润色当成 DeepSeek 已测试；禁止把键盘麦克风当成原生 SpeechRecognizer 已跑通。
- 关键路径必须在安卓真机上真开、真点、真输入、真计时，并留下可核验证据。

## 附加约束（技术栈与版权）

- 首版技术栈：Expo / React Native + TypeScript；依赖版本须与本机 Expo SDK 及官方兼容矩阵实测匹配，不提前锁死。
- 复用第三方代码/素材前必须真实执行 Reuse Audit（版本、License、依赖链、维护情况）；无 LICENSE、来源不明、GPL 源码一律不引入闭源产品；`THIRD_PARTY_NOTICES.md` 与 `LICENSE-AUDIT.md` 如实登记。
- 素材版权单独审查，不因代码库 License 而默认可用。

## 开发工作流与质量门（含 ORCA 优先）

- 遵循 SDD：Spec Kit `constitution → specify → clarify → plan → checklist → tasks → analyze → implement → converge`，保留真实命令产物与证据。
- 本宪法与用户既有 ORCA 治理规则并存：**冲突时 ORCA 治理优先**，本宪法不得制造第二套互相冲突的规则。
- 开发授权、首次发布签收、生产/凭据/不可逆操作的授权限制，均按 ORCA 既有 Human Gate 执行。
- 代码必须经自审（`docs/review/`）、真实 QA（`docs/qa/`）与产品验收追踪矩阵收口；单智能体模式下如实标注「自审」。

## Governance

- 本宪法约束优先于一般开发习惯；修订需记录变更理由与迁移影响。
- 版本策略：MAJOR＝不兼容的治理/原则移除或重定义；MINOR＝新增原则或实质性扩充；PATCH＝措辞澄清与修订。
- 合规审查：每个交付的 Phase2 收口必须核对本宪法的七条原则；复杂度必须被论证。
- 运行时开发指引：以用户 ORCA 治理规范（`AGENTS.md`、`docs/sop/`）为最高真源。
